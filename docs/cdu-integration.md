# CDU 专区接入与验收记录

分支：`cdu/academic-zone`。开发主机：macOS arm64 / Bun 1.4.2。记录日期：2026-10-10。

## 当前实现

两校导航共存。成都大学使用独立原生学校窗口、自动学校入口导航、直连 Session、账户摘要及按学号/学期隔离的原子 JSON 缓存。四个类别（个人资料、课表、成绩、考试安排）与四个只读 Agent 工具共用服务。渲染层通过专用 Hook 调用类型化 IPC，状态采用 Jotai。

在线链路当前为**已登录页面表格与学籍卡片提取**，并没有宣称取得或验证学校真实业务 API。认证联合业务顶栏、学籍卡片与同窗口 iframe 表格识别学号和姓名；页面 200、SSO 中转和验证码页面均不能结算成功。查询拒绝维护页、过期登录和账户变化。仅提取已加载分页，学期优先读取学校可见筛选或成绩行；无法识别时标注“学校当前页面”，不采信应用输入框代替服务器筛选。跨学期成绩同时按行内真实学期隔离缓存，范围仍标注为部分已加载内容。用户在学校页面完成筛选后读取。页面没有可识别表格时提示在学校窗口打开对应功能。

文件保底支持 CSV、HTML 表格、XLSX，使用已有 Cheerio / Silurus OOXML，不增加依赖。预览需指定学号和学期，确认后保存。上限：文件 8 MB、100 列、5000 行、50 张 HTML 表格。预览令牌属于原应用窗口，有效期 10 分钟；账户变化或新预览可使旧预览失效。来源、时间、账户及学期始终显示；导入数据不是学校实时数据。

账户摘要为 `cdu-account.json`，数据位于 `cdu-cache/<学号>/<学期 SHA256>/<类别>.json`。学校密码、Cookie、票据和原始 HTML 不进入配置文件。不同账户缓存分别存放，切换账户不删除另一账户文件；登出清除当前账户缓存和 CDU 分区。重启不继承 `active`。

## 本机网络配置与证据

应用在首次导航、诊断前等待 `setProxy({ mode: 'direct' })`，并关闭旧连接；应用代理设置修改后重新保持 CDU 直连。学校窗口和网络诊断共用 `persist:cdu-auth-zone`。诊断区分系统 DNS、Fake-IP、分区代理、网络不可达、认证跳转与站点拒绝，不记录认证请求地址或凭据。

Clash Verge Rev 当前订阅的规则扩展前置 `DOMAIN-SUFFIX,cdu.edu.cn,DIRECT`；脚本扩展保留原 `main` 行为，并给 DNS Fake-IP 黑名单添加 `+.cdu.edu.cn`。修改的是持久化扩展源，未手改生成运行配置。候选配置经本机 `verge-mihomo -t` 验证后，通过“重新激活订阅”生效。

## 使用与真实验收

1. 点击侧栏 CDU 专区 → 连接学校账号；直连维护时自动转向官方 VPN，也可直接点击官方 VPN。
2. 用户本人在学校窗口输入密码并完成学校要求的扫码或短信验证。软件自动点击 VPN 资源中的“数智教务”、继续学校统一认证，并尝试进入只读个人信息页；读取本人学号、姓名和业务表格后自动完成验证。未知菜单仍可手动打开个人信息，再点击“检查登录状态”。
3. 在学校页面打开目标功能、选择学期、加载所需分页，再点击专区“读取学校页面”。逐项核对本人课表周次/节次/地点、成绩和考试安排。
4. 在线仍不可用时，从学校导出 CSV、HTML 或 XLSX；选择正确类别并填写本人学号、学期，导入预览确认后保存。使用“读取本地数据”及 Agent `source=cache` 显式读取。
5. 从专区打开教务助理会绑定 CDU。普通会话明确校名优先，其次使用已有会话绑定；缺少校名时需选择学校。

已在学校真实业务页面确认本人身份卡片、成绩分页（共 28 条，首屏 20 条）和当前学期考试无记录；专区内自动提取及缓存仍需使用最新主进程重测，不能将学校页面已显示数据等同于专区读取验收。不得把行为测试中的合成数据当成在线验收。真实业务 API 尚未验证。首版不包含选退课、报名、改密或 PDF/OCR。

## 隔离桌面验收补记

使用独立 `PROFER_CONFIG_DIR` / `PROFER_USER_DATA_DIR` 与临时“CDU Acceptance”实例，没有加载正式账户配置。专区导航、账户卡、四个业务标签、诊断和官方标识已实际展示。

XLSX 保底链路已在真实 Electron 界面跑通：使用明确标记的合成工作簿，经本地 WASM 解析出两条成绩；预览阶段没有缓存文件，确认后按账户/学期原子保存，随后通过“读取本地数据”重新显示相同记录、来源与时间。该离线账户保持未连接状态，不伪装成学校登录成功。CSV/HTML 的解析与导入契约由行为测试覆盖。

用户已在隔离窗口完成官方 VPN 登录，资源列表中实测教务转发域名为 `szjw-cdu-edu-cn-s.vpn.cdu.edu.cn:8118`。原先将弹窗重定向回原窗口的方式未完成资源打开；现已适配同分区真实弹窗及空白页握手，并增加 SPA 登录检测、资源入口和统一认证自动导航，直连维护时自动转向官方 VPN。新增行为测试覆盖这些路径；新版桌面已实测点击“连接学校账号”后自动从教务维护页转入 VPN 登录页。重启后学校会话需要重新认证，登录窗口已重新弹出；真实课表、成绩、考试和在线身份仍待重测。诊断 Session.fetch 对 VPN/教务处根地址出现网络失败，尽管独立直连探测可达且 VPN 原生导航成功；保留这一差异，不将其概括为所有请求均成功。诊断仅展示标准网络错误码，便于后续定位。

进一步实测：学校资源入口的 8118 端口为 HTTP，HTTPS 握手返回 `WRONG_VERSION_NUMBER`；8119 未完成 TLS 握手，443 的证书与转发子域不匹配，未绕过证书校验。新版默认阻止此明文转发并显示兼容方式入口。用户明确阅读并确认后，仅当前运行放行编码为 CDU 资源的 `*.vpn.cdu.edu.cn:8118`；范围不包含普通校园 HTTP、其他端口及外部目标。退出账户或重启撤销授权。用户已在当前隔离验收实例阅读风险并明确授权，界面已实测显示“本次已允许学校旧版 HTTP 转发”。本次授权不写入账户摘要，默认配置保持关闭；用户随后完成 VPN 登录，软件正在尝试教务业务认证，真实个人数据仍未验收。替代路径为校园网或学校官方 SSL VPN 客户端。

## 真实页面结构适配补记

实际系统为超星智慧教务，菜单位于“信息查询”：我的课表、全部成绩查询、考试查询。已按真实菜单名称适配自动只读导航，顶栏“姓名 / 学号 学生”及首页学籍卡片用于身份读取；业务数据位于 iframe。EasyUI 的表头、数据区和冻结列按 `field` 合并，避免把第一条成绩当成表头或错配学分。加载遮罩不作为无记录结算；隐藏的旧 iframe 不参与当前页面读取。再次连接优先复用业务窗口，避免重复打开 VPN 和弹窗。

上述解析使用去标识的合成结构回归；代码和文档不含真实学号、姓名、单科成绩或认证票据。学校页面已见真实数据，最新解析器的专区端到端核对仍待完成。

Sangfor 的资源页保留屏外密码控件，曾被通用表单检测误认为待登录。现按已观察的 `/portal/#!/service` 与 `/portal/#!/login` 路由区分；该判定只描述门户状态，仍需业务域中的本人身份和业务数据联合验证。对应回归已加入。

## 账户卡一次输入登录（2026-10-11）

经用户明确要求，CDU 改为在专区账户卡输入本次学号和密码，主进程在同一隔离 Session 内通过学校原生表单衔接数智教务、官方 VPN 与统一认证。密码只用于本次连接，不落盘或交给 Agent；提交后立即清空渲染状态。学校扫码、短信、验证码和 VPN 声明交由本人处理。后台连接默认限时 2 分钟，首次人工验证阶段给予 10 分钟，轮询不无限续期。

Electron `0.15.143`、shared `0.1.66`。公开表单检查、本地合成 Electron DOM 和隔离桌面账户卡验证通过；全仓 3466 项测试通过、4 项 Windows 平台测试跳过，9 包类型检查及主进程/Preload 构建通过。真实账号已通过统一身份认证，账户卡自动连接后成功激活本人账户并读取当前学期课表。VPN 单独返回校验错误，未重复尝试或标为验收通过。

HTTP 200 内含 403 的“页面正在修复”与本机网络出口有关：TUN 中的 DIRECT 仍返回拒绝内容，绑定物理网卡的 IPv6 可正常跳转统一认证。用户允许后，仅为数智教务域名增加 IPv6 优先物理网卡直连，先备份并校验，保留 TUN 和 AI 代理。学校成绩菜单还存在双斜杠重定向、首页隐藏表格误匹配和 jqGrid 表头/数据分离问题，已增加 BDD 回归并修复。记录不包含真实账号、密码或票据。详细选择依据、最新验收结果与恢复方式见 [一次输入登录方案](cdu-single-login.md)。

最终隔离桌面验收：账户卡一次输入后自动完成统一认证和本人身份激活，真实课表、成绩当前页 20 条、个人资料均已提取；考试默认筛选明确无记录，应用保留空数组。成绩跨学期缓存按真实学期拆分，界面回读 14 条缓存并标注来源。仍只覆盖学校已加载页面；不自动翻页、变更筛选或宣称其他平台已接通。
