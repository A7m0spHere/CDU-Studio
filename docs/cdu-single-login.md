# CDU 一次输入登录方案与验证（2026-10-11）

## 目标与当前范围

用户在 CDU 专区账户卡输入一次学号和学校密码，软件自动完成数智教务入口、必要的官方 WebVPN、统一身份认证与本人身份核对。用户明确选择先跑通数智教务；本次没有宣称接通办事大厅、图书馆或其他平台。

学校要求扫码、短信、验证码或同意 VPN 使用说明时，显示学校原生窗口，由用户本人处理。学校认证通过前，不能以页面 HTTP 200、VPN 资源列表或 SSO 重定向作为教务接入成功的依据。

## 对接方式的选择

选择与现有 CDUT 相同的核心方式：**学校原生浏览器认证 + 同一隔离 Session 复用 + 各业务独立验证**。

- CDUT 的账户卡、后台窗口、学校页面原生密码处理及共享 `CDUT_AUTH_PARTITION` 可以作为设计参考。
- CDU 的认证地址、表单和业务落点独立适配，不复制 CDUT 的 CAS service URL、青果接口或 Cookie 规则。
- 保留 Chromium 的学校页面脚本处理密码与表单，不自行逆向密码算法或伪造票据。业务查询仍使用既有已登录页面提取，真实教务 API 未验证。页面筛选、成绩分页及其他校园平台仍需要各自核对。
- WebVPN 按学校手册从资源列表进入“数智教务”，不猜测或拼接带票据的转发链接。

## 学校官方依据

- [统一身份认证使用指南](https://nic.cdu.edu.cn/info/1035/1785.htm)：学校统一认证入口为 `https://id.cdu.edu.cn`，校园 VPN 使用统一认证账户。
- [校园 VPN 使用手册](https://nic.cdu.edu.cn/info/1035/1778.htm)：支持 WebVPN 和 SSL 客户端；WebVPN 使用学校统一认证账号，校内资源须从资源列表进入。
- [数智教务登录指南](https://jw.cdu.edu.cn/info/1191/12080.htm)：教务处公布的业务入口指向 `szjw.cdu.edu.cn`。
- [多因子认证通知](https://nic.cdu.edu.cn/info/1047/2399.htm)及[登录指南](https://nic.cdu.edu.cn/info/1035/2396.htm)：学校计划自 **2026-10-12 零时**启用账号密码后企业微信扫码或短信验证。产品不能承诺只凭密码永久免验证。

## 本次已实现

1. `CduLoginForm` 使用 Jotai 管理账户卡输入；提交后立即清空渲染状态中的密码。
2. `CDU_ZONE_IPC_CHANNELS.LOGIN` 只允许应用主窗口主框架调用，主进程临时接收本次凭据。四个 Agent 工具不提供密码参数或登录能力。
3. 清理旧学校认证分区状态后，在隐藏原生窗口中打开官方应用导航公布的 `https://szjw.cdu.edu.cn/admin/caslogin`。首次认证遇维护或拒绝时转入学校官方 VPN；账户已验证后，业务错误不自动切换 VPN 或破坏原会话。
4. 只在精确学校认证主机与登录路径上填写。脚本执行前后检查来源，不向普通业务页、任意 CDU 子域、外部页面或未经确认的旧版 HTTP 转发填写密码。
5. 通过原生 input value setter 与 `input/keyup/change/blur` 事件通知学校前端，等待登录按钮就绪；每个认证阶段提交一次。结果不确定时不重复提交。
6. 排除 Sangfor `.hidden-box` 透明假输入框、屏外控件和不可见祖先。识别验证码及动态口令，不将学校密码填入一次性口令框。
7. 学校声明复选框即使是隐藏原生 input 配合可见自定义控件，也会等待本人确认，不自动勾选。
8. 扫码、短信或验证码时显示学校窗口。后台连接默认限时 2 分钟；首次进入人工验证阶段给予 10 分钟处理时间，轮询不会无限续期。成功、密码被拒绝、取消或到期后释放主进程中的密码引用。
9. 只有可读取的本人身份与业务数据联合成立，且学号与本次输入一致，才激活账户。成功后隐藏认证窗口，并继续由同一 Session 支撑查询。
10. 取消、登出与导航代次检查防止过期异步请求重新打开窗口。学校错误只映射为受控提示，不把包含凭据的原始异常传到渲染层。
11. 超星 jqGrid 依据 `th[id]` 与 `td[aria-describedby]` 合并分离表头和数据，快照先排除首页隐藏弹窗中的表格，再跳过隐藏主键、占位行及分页控件，保留真实空记录。
12. 学校业务网格首次加载可超过 3 秒，等待上限增至 40 轮（每轮间隔 250ms），识别 jqGrid 加载遮罩；超时仍显示学校页面要求核对，不伪造数据。
13. 学校成绩菜单实测包含 `/admin//xsd/…`，服务端会回到嵌套首页；仅规范同源菜单 pathname 的重复斜杠，保留学校原生点击行为及查询参数，不猜测业务 API。

密码不写入业务 JSON、工作区文件、日志或提交；Cookie 由 Chromium 隔离 Session 自身管理，不复制到应用账户配置。没有增加第三方依赖。本次 Electron `0.15.143`、shared `0.1.66`。

## 已取得的证据

- 在全新非持久化 Electron Session 中检查学校公开页面，未使用真实凭据：统一认证是 Ant Design 登录表单，用户名字段为 `name=username`；VPN 为 Sangfor，存在透明 `.hidden-box` 防填充框、自定义免责声明复选框和原生登录按钮。
- 使用本地协议拦截的合成页面，在真实 Electron 中验证：统一认证原生 setter 与事件能启用并点击登录按钮；Sangfor 假输入框不写入密码；免责声明、验证码等待本人处理。合成验收没有向学校提交账号密码。
- 在隔离 `PROFER_CONFIG_DIR` / `PROFER_USER_DATA_DIR` 的实际桌面界面显示并操作了新的账户卡；未加载正式 AI 渠道配置。
- 全仓测试 **3466 pass / 4 skip / 0 fail**，390 个文件；9 个包类型检查、架构边界、主进程与 Preload 构建通过。四个 skip 属于 Windows PowerShell 平台测试。

真实账号已通过学校统一身份认证，随后在隔离桌面实例中完成账户卡一次输入、自动认证、本人身份激活及四类查询：当前学期课表 13 个网格行、成绩当前页 20 条（跨学期）、个人资料 8 个字段行，考试页在当前默认筛选下明确显示“没有记录”。成绩按行内学期拆为两份缓存（6/14 条）；已在界面回读其中 14 条并确认“学校页面 · 本地缓存”来源标注。课表网格行数不是课程门数，考试当前筛选无记录也不代表所有批次为空。此前 VPN 返回密码错误与主身份认证结果不同，未继续重复尝试，也不宣称 VPN 已验收。此记录不包含真实学号、姓名、密码、Cookie、票据或成绩。

## 本机代理诊断与恢复

HTTP 200 内含“页面正在修复 / 403 Forbidden”不能直接判为学校停机。实测 Clash TUN 开启且命中 DIRECT 时仍返回拒绝内容；IPv6 Socket 绑定物理 `en0` 后返回正常 302 登录跳转。经用户明确允许，在当前订阅扩展中仅增加 `DOMAIN,szjw.cdu.edu.cn,CDU-IPv6-DIRECT`，直连节点使用 `ip-version: ipv6-prefer` 与 `interface-name: en0`。该配置属于本机网络修复，不随项目代码自动应用到他人机器；其他网卡名称或无 IPv6 网络须重新诊断。

原 rules/proxies 扩展已备份至 Clash 配置目录的 `cdu-backups/20261011143057-ipv6/`，含 SHA256 清单及 `RESTORE.txt`；按说明还原两个扩展并重新激活订阅即可撤销。配置校验和应用后实际路由均通过，TUN 保持启用；`api.openai.com` 的无凭据 TLS 探测仍经过代理，未调用模型 API。备份含本机代理配置，禁止加入 Git。

配置依据：[Mihomo 直连出站](https://wiki.metacubex.one/config/proxies/direct/)、[通用出站参数](https://wiki.metacubex.one/config/proxies/)。

## 后续平台扩展

数智教务端到端核对通过后，再按平台逐个增加入口、身份验证与只读数据适配器，共用 `persist:cdu-auth-zone`。是否真的可以免输密码，取决于该平台是否接入学校统一认证、当前 SSO 会话是否有效以及学校验证策略；同一套账号密码不等于所有平台共享登录态。

首批后续候选是网上办事大厅及图书馆，但需要分别验证，不能把门户主页可达当作平台接入成功。
